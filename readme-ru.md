# Проектирование систем пакетной обработки (ETL/Batch) + Observability

**Суть вызова:**
* 4 кейса проектирования архитектуры и реализации PoC конвейеров пакетной обработки данных.

**Ландшафт:**
* **Архитектура**: ETL, Orchestration
* **Технологии**: Apache Airflow, Java Spring Batch, Python, Micrometer 
* **Инфраструктура**: K8s + CronJob, Prometheus, Grafana-стек, ELK-стек
* **Документация**: ADR, C4, Pandoc

## 📌 Краткое описание результата
1. Выбор технологий и реализация Proof of Concept для автоматизации пакетной обработки данных в трех различных бизнес-кейсах:
   - маркетинговая аналитика,
   - генерация B2B-прайс-листов
   - выгрузка данных для грузоперевозок.
  
2. Кейс TradeWare: Оптимизация legacy пакетной обработки.  

## 🧊 Архитектурный выбор и Proof of Concept (Task 1-3)
1. Выбор ETL-платформы для маркетинговой аналитики (Task 1)
   - Задача:
     - Объединение данных из CSV, PostgreSQL и Kafka для BigQuery/Redshift. Около 1 млн записей за запуск  
   - Результат:
     - Обоснование выбора Apache Airflow + Apache Spark
     - Локальный Proof of Concept пайплайна с обработкой ошибок и email-уведомлениями.

2. Дизайн модуля генерации прайс-листов (Task 2)
   - Задача:
     - Ежедневная выгрузка 20к строк в 6:00 для B2B-клиентов. Объём данных 5 000–10 000 строк. 
   - Результат:
     - C4-диаграмма (To Be) состояния системы.  
     - Обоснование выбора Python Script + K8s CronJob
     - План имплементации

3. Распределенный планировщик в K8s (Task 3)
   - Задача:
     - Выгрузка данных аналитики по перевозкам (до 1 млн событий в день) в 20:00 посредством KronJob.
   - Результат:
     - конфигурационный файл CronJob для Kubernetes.  

## 🧊 Кейс TradeWare: Оптимизация legacy пакетной обработки (Задания 4-6)
Выделение ETL пайплайна из монолитной инфраструктуры для обработки пиковых нагрузок без деградации производительности Prod сервисов. Обеспечение надежности и наблюдаемости модуля пакетной обработки.

### 🎯 Ключевые показатели и цели
- Масштабируемость: 
  - Обеспечение 100–150 параллельных загрузок файлов в пиковые часы.
- Производительность: 
  - Обработка отчётов объёмом 2000 строк менее чем за 30 секунд.
- Надежность:
  - Внедрение механизмов Retry и Fallback для интеграций с внешними API и базами данных.
- Наблюдаемость:
  - Сокращение MTTR за счет централизованного сбора логов и метрик.  

### 🛠 Специфика кейса
| **Критерий**        | **Решение / Обоснование**                                                                           |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| **Тип нагрузки**    | Смешанная: **Batch обработка** (отчёты об остатках) и **OLTP** (обновление номенклатуры).           |
| **Стек технологий** | Java 11 (Spring Batch), PostgreSQL, Kafka, Airflow, ELK, Prometheus, Grafana.                       |
| **Инфраструктура**  | Развертывание в **Kubernetes (MiniKube)** с использованием Docker Compose для локального окружения. |

### 📐 Архитектурные решения
- Спроектировала ETL пайплайн на основе Spring Batch. (Task4)
- Спроектировала модуль наблюдаемости Prometheus + Grafana стек (Task5)

## 💻 Proof of Concept
  * Apache Aiflow Python пайплайн с обработкой ошибок и email-уведомлениями (Task1)
  * Плановый запуск через K8s CronJob (Task3)
  * Воркер для обработки данных с обогащением на основе Spring Batch (Task4)
  * Модуль наблюдаемости Micrometer + Prometheus + ELK-стек (ElasticSearch, Logstash, Kibana) и дашборды ключевых метрик (Task5, Task6)

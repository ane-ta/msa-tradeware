
Отличное задание на проектирование системы пакетной обработки (batch processing). Учитывая вводные данные — работу в облаке с микросервисами, небольшой объем данных (до 10 000 строк) и отсутствие сложной логики трансформации — я помогу подготовить решение. (p. 1)
Ниже представлен разбор, который ты можешь использовать для заполнения требуемых документов.
------------------------------
1. Обоснование технологического решения
Для такой задачи (простая выгрузка по расписанию) оптимальным выбором будет K8s CronJob.

| Критерий | Spring Batch | Apache Airflow | K8s CronJob | Spark |
|---|---|---|---|---|
| CRON-расписание | Требует запущенного инстанса | Из коробки (сложно для 1 задачи) | Native поддержка | Требует планировщик |
| Сложность логики | Высокая (Overkill здесь) | Средняя (Python-based) | Низкая (простой скрипт/SQL) | Высокая (для Big Data) |
| Ресурсоемкость | Высокая (JVM) | Высокая (инфраструктура) | Минимальная (поднимается по требованию) | Очень высокая |
| Масштабируемость | Средняя | Высокая | Высокая (native K8s) | Экстремальная |
| Сложность в облаке | Средняя | Высокая | Нулевая (уже в K8s) | Высокая |
| Мониторинг | Micrometer/Actuator | Своя панель | K8s events/Prometheus | Spark UI |

Вывод: Поскольку инфраструктура уже работает в K8s, а задача тривиальна (простой SQL-запрос и экспорт в CSV), использование K8s CronJob с легковесным образом (на Python или Go) является самым эффективным и дешевым решением. (pp. 1-2)
------------------------------
2. С4-диаграмма контекста (To Be)
В системе To Be появляется новый компонент внутри кластера K8s.

* User/Client: B2B-клиенты, получающие прайс-листы.
* System (Price Exporter): K8s CronJob, запускающийся в 06:00.
* Database: PostgreSQL (существующая БД). (p. 1)
* Storage: S3-совместимое хранилище или FTP-сервер (куда складываются CSV).

Описание работы:

   1. K8s CronJob запускается по расписанию в 06:00.
   2. Приложение внутри контейнера выполняет JOIN-запрос к таблицам products, categories, clients и client_prices. (p. 1)
   3. Результат форматируется в CSV/XLS.
   4. Файл загружается в облачное хранилище или отправляется клиенту.
   5. После завершения работы Pod удаляется, освобождая ресурсы.

3. План конфигурации и имплементацииа. Конфигурация

   1. Docker-образ: Создать легковесный образ (например, на python:3.9-slim), содержащий скрипт выгрузки и драйвер для PostgreSQL.
   2. K8s Secret/ConfigMap: Описать параметры подключения к БД (хост, логин, пароль) и параметры доступа к хранилищу.
   3. CronJob Manifest: Описать YAML-файл с расписанием schedule: "0 6 * * *" и лимитами по ресурсам (CPU/RAM).

b. Имплементация

   1. SQL Query: Написать оптимизированный запрос, объединяющий данные о продуктах и ценах для каждого клиента.
   2. Script: Реализовать логику итерации по списку клиентов, генерации индивидуальных файлов и их именования.
   3. CI/CD: Настроить pipeline для сборки образа и деплоя манифеста CronJob в кластер.
   4. Logging: Настроить вывод логов в стандартный поток (stdout) для сбора системой мониторинга (например, ELK или Grafana Loki). (p. 2)

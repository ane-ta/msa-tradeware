# План внедрения

## 1. Конфигурация (Подготовка среды)

На данном этапе подготавливается инфраструктура Kubernetes и права доступа для безопасной работы скрипта.

### 1.1. Управление секретами

- Создание манифеста для подключения к **PostgreSQL** (host, port, user, password).
- Настройка секретов для авторизации в **S3 Storage** (Access Key ID, Secret Access Key).

### 1.2. Сетевые политики

- Разрешение трафика из `Business Namespace` до порта БД (5432) во внутреннем сегменте.
- Настройка исходящего трафика (Egress) для загрузки файлов в S3 по протоколу HTTPS.

### 1.3. Подготовка облачного хранилища (S3)

- Создание целевого бакета (bucket) для прайс-листов.
- Настройка **Lifecycle Policy** для автоматической очистки файлов старше 30 дней.

### 1.4. Реестр образов (Container Registry)

- Создание репозитория для хранения Docker-образа скрипта в корпоративном Registry.

## 2. Имплементация (Разработка и деплой)

Процесс создания и запуска логики выгрузки.

### 2.1. Оптимизация SQL-запроса

- Написание и тестирование SQL запроса.
- Проверка наличия индексов по полям связей.

### 2.2. Разработка Python-скрипта

- Использование `psycopg2` для чтения данных из БД.
- Формирование CSV через стандартную библиотеку `csv`.
- Загрузка в S3 через `boto3`.
- **Важно:** Реализация атомарной записи (запись во временный файл -\> загрузка в S3 -\> проверка целостности).

### 2.3. Контейнеризация

- Создание Dockerfile на базе `python:3.9-slim` (минимизация размера образа).
- Оптимизация слоев для быстрой сборки и деплоя.

### 2.4. Создание манифеста K8s CronJob

- Установка расписания: `schedule: "0 6 * * *"`.
- Настройка лимитов ресурсов: `requests/limits` (128MB RAM / 100m CPU).
- Настройка политик надежности: `backoffLimit: 3` и `activeDeadlineSeconds: 300`.

### 2.5. Мониторинг и Observability

- Настройка вывода логов в `stdout` в формате JSON.
- Настройка алерта в **Grafana** на отсутствие успешного завершения задачи к 06:15.
